# Sip & Tell

Telegram Mini App с ботом: чайный дневник для друзей. Оценки чая, настроение и обстоятельства чаепития, свой отзыв, друзья и сравнение оценок, модерация.

Код начинался как форк идей из `D:\MyRepositories\Nightpour` (он остаётся архивом). Продукт описан в `docs/PRODUCT.md`, идеи собираются в `docs/IDEAS.md`.

## Как работаем (эксперимент)

- Владелец заказчик: решает UI/UX и принцип работы, предлагает идеи. Claude пишет весь код, тесты и документацию.
- Отдельных HTML-макетов нет. Новый экран сначала собирается в живом клиенте (`web/`) на тестовых данных, по образцам с 21st.dev и токенам дизайн-системы. Для важного экрана делается 2–3 варианта, владелец выбирает. Каждый элемент интерфейса (карточка, кнопка, шторка, навигация) обсуждается по отдельности: Claude предлагает 2–3 способа реализации с живым примером, владелец выбирает. Правило описывается словами. После согласования подключается сервер. Спорное (стек, структура) выносится владельцу с рекомендацией, молча не решается.
- Новая идея сразу записывается в `docs/IDEAS.md` и в Singularity (проект «Чайный дневник», см. skill `idea-routing`), в работу берётся после решения владельца.
- Каждый шаг заканчивается проверкой: тест или запуск. Владельцу показывается экран или скриншот, а не пересказ.
- Каждый блок работы живёт в своей ветке от `master`: `mockup/<экран>`, `feat/<блок>`, `docs/<тема>`. Одна ветка, одна тема.
- Коммиты мелкие и со смыслом, Claude делает их сам после каждого проверенного шага и пушит ветку. В `master` ветка попадает только через pull request, который сливает владелец. В PR описание и скриншот. Мелкие правки README и правил можно коммитить прямо в `master`.
- Секреты (токен бота, ключи, строки подключения) лежат только в окружении сервера или `.env`, Claude их не читает и не пишет в репозиторий.

## Стек

- Сервер: C#, ASP.NET Core на .NET 10, один процесс. Раздаёт клиент, API и вебхук бота. Решение `SipAndTell.slnx`, база PostgreSQL.
- Клиент: React, TypeScript, Vite, `@twa-dev/sdk`. Анимации только Motion (`motion`). Образцы блоков берутся с 21st.dev и переписываются под тему, готовые блоки не копируются.
- Первый круг только для друзей. Публичный запуск в него не входит.

## Дизайн (решения владельца)

- Только тёмная тема, светлой нет. Палитра «Дом»: коричневый и янтарный на тёмном тёплом фоне.
- Стеклянный интерфейс в стиле «Жидкое стекло»: очень прозрачный, с бликом по краю, светом за пальцем и живым фоном, много анимаций (Motion). Это решение главнее правила skill `telegram-miniapp-ui` про тему Telegram.
- Главная в варианте B: крупные карточки чаепитий.

## Стиль

Перед правкой читай skills проекта: `sipandtell-code-style`, `safe-persistence`, `telegram-miniapp-ui`. Для дизайна можно подключать плагин `ui-ux-pro-max`, но правила `telegram-miniapp-ui` (скорость первого экрана, без веб-шрифтов) главнее.
